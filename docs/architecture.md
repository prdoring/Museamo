# Architecture decisions

## One native source of truth

React 19 + TypeScript + Vite + Tailwind inside Capacitor 8 implement review. Kotlin owns Room/SQLite, the capture activity, widget configuration, tag picker, drafts, and Storage Access Framework backup. Native capture never starts a WebView. The bridge exposes typed queries/mutations, library/profile operations, native compose/configuration launch, backup pickers, and `dataChanged`. All mutations serialize on one repository executor and use Room transactions where multiple records change. Refresh on WebView resume reconciles notifications missed while the app was closed.

Entries have UUIDs, plain text, creation/modification timestamps, star state, tag IDs, and optional capture-profile provenance. Tag IDs are stored as JSON arrays on entries/profiles/drafts; the repository transactionally enforces referential cleanup and validates assignments. Query pagination runs in SQL; tags are matched using quoted UUID tokens. Tags have unique normalized names. Schema exports are committed and destructive migration fallback is forbidden. Schema v1 is the initial baseline; v2 adds media metadata and ordered media IDs to entries/drafts through an explicit tested migration.

Capture profiles have independent UUIDs; Android widget IDs are mappings, never portable identity. Copying a profile into a new widget creates an independent profile. Widget removal removes its binding and draft but retains its profile and all entries. Profiles remain editable/reusable in Settings. A fixed profile supports zero or more tags; a picker supports zero or one selected default. On opening a fresh composer, copy defaults into a durable draft with an entry UUID. Reuse that UUID when committing the draft, preventing duplicate saves. A saved draft's actual tags survive subsequent profile changes. Successful entry insertion and draft deletion occur atomically.

## Bridge

`src/data.ts` defines the app-facing contract. `queryEntries` accepts text and star/tag filters, a `(beforeTime, beforeId)` cursor and limit, and returns entries with `hasMore`. Legacy offset calls remain supported. The cursor uses the existing creation-time/ID index so inserting a new thought does not duplicate the next page. `getEntry` fetches a saved/edited entry without resetting loaded pages. `library` returns tags with SQL-computed counts and profiles. Entry edits preserve identity/creation time/provenance. Delete is immediate; the UI retains the deleted record for Undo and repository restoration revalidates tag/profile references. Compose launches a native activity for a result and resolves with cancelled/saved plus an optional entry ID. Widget configuration launches its native activity. Star toggles do not change the text-edit timestamp. Backup import/export use native system document pickers rather than granting the WebView arbitrary file access.

## Portable backups

Thought formatting uses Markdown within the existing text field. Both editors preserve this source through drafts and mutations, and JSON backup v1 retains it unchanged. Semantic clipboard HTML is converted at the input boundary, never stored as executable HTML. React renders safe elements; native preview uses Markwon without an image loader. Copy exports semantic HTML and readable plain text. Shared formatting fixtures check the TypeScript and Kotlin converters. Future connection adapters must choose the destination's supported text representation explicitly.

Legacy version 1 JSON contains `format: "museamo"`, `version: 1`, `exportedAt`, `tags`, `profiles`, and `entries`. No drafts, Android widget IDs, or secrets. Export materializes a consistent transaction snapshot. Import validates the entire document before mutation and applies it transactionally. Unknown versions, malformed types, invalid IDs, dangling references, duplicate IDs/names, and unreasonable file sizes are rejected with an actionable message. Existing identical IDs/content are skipped. Conflicts are assigned fresh IDs and references are remapped; existing content is never silently replaced. Normalized tag names resolve to an existing tag to avoid indistinguishable duplicates. Same-ID renamed tags with distinct names are preserved separately. Profiles import without widget bindings. Entries reference remapped profile/tag IDs.

## Future delivery — documented only

Connection configuration: adapter type, credential reference, trigger (`manual` or `onCreate`), filter (`all` or `anyTag` with stable tag IDs), destination settings. All-entry filters match untagged entries; tag filters do not. Evaluate against final capture tags once on successful creation. One delivery per matching connection regardless of how many tags match. Manual sending bypasses automatic filters. No automatic historical backfill, star-triggered posting, or delivery on later tag/edit changes.

Later, atomically insert entry and eligible outbox records. A native WorkManager dispatcher delivers immutable snapshots without React. Track pending/sent/failed/uncertain per destination, use stable attempt identities, and honor provider idempotency. An ambiguous non-idempotent timeout must not silently duplicate a public post. Explicit resend creates a new delivery; local edits/deletes never retract sent content by default. Keep backup, REST/webhook delivery, and social publication separate capabilities. Verify each provider's direct-device authentication; store credentials using Keystore-backed storage. Do not embed server secrets in an APK. Incoming webhooks and multi-device conflict resolution require separate designs.

## UX preview and hashtags

The browser implementation of the same typed bridge is in-memory. It provides sample, empty, large-library, and failure scenarios; refresh resets it. It never imports or writes real Android data. Kotlin and TypeScript share hashtag JSON fixtures. Inline hashtags remain plain text, and new tag creation is part of the native save transaction. Editing an unchanged historical hashtag whose tag was renamed or removed does not silently recreate the old tag. Explicit selections are stored separately from inline-derived selections in drafts; saved entries keep the final union.

## Rich media

Media IDs reference immutable originals under private files/media; each media row records MIME type, original filename, size, dimensions, duration and SHA-256 checksum. Entries and drafts retain ordered ID arrays. The bridge serializes metadata as attachments, accepts attachmentIds for mutations, and resolves files to the private /_media/{UUID} route. Originals and binary data never cross the JSON bridge. The custom Capacitor WebView client restricts this route to registered media and implements bounded HTTP byte ranges for seeking; arbitrary Capacitor file/content routes are blocked.

System photo-picker selection falls back through AndroidX on older devices. Imports stream to private storage, validate size and device decoding, and generate independent thumbnails. Failed batches roll back their files. Durable draft references are written before imported selections become ready. Repository mutations serialize on Store.executor. Process-start cleanup removes unreferenced files; live edit imports and pending Undo actions pin media until release. Draft discard and edit cancellation cannot remove a file still referenced by a saved thought.

The v2 ZIP format starts with manifest.json and contains media/{UUID} entries. The manifest extends the existing portable data with attachmentIds and media records, without filesystem paths. Exports and imports stream file contents, bound each file, check SHA-256, reject duplicate/unknown archive paths, and apply metadata in a transaction. Imported entry/profile/tag conflicts retain existing remapping semantics. Originals moved before the transaction are removed on rollback and recovered by startup cleanup after process interruption. Legacy text-only JSON imports remain supported.

Remote media is render-only, parsed from Markdown's syntax tree with code/HTML excluded. Recognized HTTPS direct-file links and YouTube/Vimeo players load only when visible and never autoplay. Unsupported links keep external-open behavior. The HTTPS WebView origin uses the Android application ID to supply YouTube's required client referrer. No local files or post text are sent to embed providers.

## Post locations

Room schema v3 adds nullable location JSON to entries/drafts, searchable resolved/user labels on entries, and a durable draft location-attempt flag. Explicit 2→3 migration composes with 1→2. Portable location metadata contains latitude/longitude, accuracy, capture timestamp, a request token, optional feature/address/locality, and a separate user label. Validate coordinates and metadata at bridge/backup boundaries. No background location permission is declared.

Location JSON also accepts optional `city`, `region`, `country`, and `countryCode` fields. Native geocoding retains the full address and legacy locality alongside these fields. Display labels combine the custom/detected place name with city and abbreviated US state, or city and country elsewhere. Full addresses remain searchable and included in backups. Formatting never rewrites saved metadata or thought timestamps; older US localities can be abbreviated directly, and older records without country metadata retain the locality they already contain. This presentation update requires no new database migration. Shared fixtures keep Kotlin and web formatting consistent.

LocationPermission requests foreground permission once on first app opening (or a fresh widget composer), only while device services are on. Automatic capture defaults on and respects a later explicit opt-out. Manual pin actions request permission directly and do not require a Settings visit. LocationCapture checks permission and enabled services before reading a recent OS position (at most 60 seconds old) or subscribing for a new fix; it cancels after 10 seconds or activity pause. A fresh composer attempts once; resumed drafts and removals do not restart automatic capture. Posting snapshots whatever location is ready without waiting. Geocoding runs on a separate executor and cannot hold the serialized repository queue. Enrichment checks the complete original location before updating a saved post; user edits, replacement, removal, and deletion win.

The bridge adds locationSettings, setLocationEnabled, currentLocation, and openLocation. currentLocation is an explicit action that requests permission if needed and returns both coordinates and an availability status; unavailable results produce composer feedback instead of disappearing silently. Existing draft/entry mutations accept optional location; omitted preserves existing metadata, explicit null removes it. queryEntries accepts located and retains cursor pagination plus search/tag/star filtering. The map fetches all located pages independently of the feed. Leaflet renders OSM standard raster tiles only on map views, with visible attribution, default HTTP caching, and a Museamo identifier appended to the Android WebView user agent. All post content and custom labels stay local.

MediaBackup exports version 3 ZIP manifests. Versions 1 JSON and 2 ZIP import with no location; version 3 imports validated canonical location metadata and preserves existing conflict-copy semantics. Drafts and the device permission/opt-in preference are not exported.

## Checklist categories

Room schema v4 adds `tags.type` (`standard` or `checklist`, default `standard`) and `entries.completed` (default false) through a 3→4 migration. Checklist eligibility derives from the entry’s assigned tag IDs and the current tag types; completion belongs to the entry and remains stored when eligibility is removed. Captured entries always start unchecked. Tag renames and native callers omitting type preserve the existing type.

The bridge exposes these fields, optional `saveTag.type`, and `setCompleted({id, completed})`. Completion validates current eligibility and updates only the completion field. No text, formatting, location, provenance, or edit timestamp changes. Restore/Undo retains completion. Browser preview implements the same behavior.

`queryEntries.order` defaults to `newest`; `checklist` requires a Checklist tag filter and orders by `(completed ASC, createdAt DESC, id DESC)`. Its cursor adds `beforeCompleted` to `beforeTime`/`beforeId`. Standard queries and Map keep chronological order. After a completion or type mutation, the app invalidates cached/in-flight results and reloads the loaded prefix before permitting pagination. Failed refreshes leave pagination disabled until Retry succeeds. Section and date dividers describe the two sorted groups.

The optional `queryEntries.checklistOnly` filter selects entries currently belonging to any Checklist tag. Native chronological queries apply an `EXISTS` predicate before their limit/cursor, preventing duplicates for entries with several Checklist tags; browser queries apply the same eligibility filter before sorting and pagination. Stream exposes this through one To-dos toggle, with separate cache/scroll keys and stale-request invalidation. Checked entries remain included. This is query-only and adds no schema or data migration.

MediaBackup now exports version 4 ZIP manifests with strict category-type and boolean-completion validation. Legacy versions 1–3 import as Standard/unchecked. Same-name tags retain their local type under existing import conflict rules, and incoming completion is retained even if currently hidden by that local type. The legacy v1 JSON helper omits checklist metadata; production exports use v4. Completion differences participate in the existing conflict-copy and repeated-import deduplication logic.

Native checklist icons are presentation only: raw tag names, inline hashtag text, picker selections, draft defaults, and capture semantics are unchanged. Compact widget tiles still omit tag controls. Narrow cards use the checklist icon in the existing tag space; wider layouts include both icon and name.
