## Review scope and remaining checks

Follow-up fixes address three reports from the first local build. Newly opening a saved empty Android composer now clears its old automatic location attempt and captures afresh; existing text or attachment drafts and saved-instance recreation preserve their state. The mounted feed now refreshes edits and deletions while scrolled, preserves the reading anchor, and reserves the new-thought banner for actual insertions. Local saved changes wake replication immediately instead of waiting for the 30-second retry timer, and original transfers yield at chunk boundaries to queued metadata.

The feed bug was reproduced against the old behavior and verified with remote delete/edit, overlapping refreshes, queued native composition, and 110-item pagination. The final real two-profile Windows WebView2 run measured ordinary native save-to-visible-feed updates at 486–617 ms. Ten rounds of simultaneous two-sided saves took 472–807 ms while native builds were running. The harness uses actual SQLite writers and encrypted LAN sessions without manual Sync now or navigation; these are local-machine measurements, not a guarantee for physical Wi-Fi.

The adversarial follow-up review found crossed connection races and a quarantined group's dirty-wake retry loop. A 20-round simultaneous-write regression failed before connection arbitration and passed afterward. Both authenticated peers now keep the connection initiated by the lower device ID when both dial together. Live outbound contenders are tracked separately from dialing reservations and cleared before replica teardown, so an old thread tail cannot discard a fresh save. The tail regression failed before that distinction and now requires delivery while an old reservation stays held for one second, followed by idle state without another dirty wake. Idle dirty wakes are consumed before quarantine errors. The reviewer checked the fixes and reported no remaining blocker. Existing revocation and teardown fences remain in place. Android widget-only captures retain the documented later-resume/background behavior.

Implementation specialists reviewed each other’s native boundaries, followed by an independent adversarial review. Regression tests cover concrete issues found during review: staged bodies acknowledged too early, purge proofs bypassing removal anchors, cancelled pairing exposing summaries, restart callback races, mutually cancelling removals, erased cross-origin history blocking catch-up, archive namespace ambiguity, and historical tag aliases losing associations on restore.

The independent review also found Android media authorization using private draft/pin references and active sessions rechecking removal only periodically. Shared-media authorization now excludes private draft/pin references, and membership changes fence each data callback and outgoing encrypted record. The reviewer checked both fixes and reported no blocking regression in that focused verification. Bytes already transmitted cannot be recalled.

The broader Android media suite caught corrupt PNG picker input being accepted by the codec fallback. Local imports again reject broken baseline images atomically while retaining modern codec originals. A dedicated regression checks corrupt-PNG rollback and HEIC retention.

Conflicting membership controls fail closed and preserve local writing. A removed key relayed by a stale trusted peer can still force quarantine; separately anchored control history is needed to eliminate this denial-of-service case. See [trust and recovery behavior](offline-sync.md).

A false discovery hint can also lead to a connected host that stalls its handshake. That temporary arbitration contender may delay a genuine incoming sync until timeout and retry; it cannot bypass identity verification or access library content.

Physical Android Wi-Fi with no internet, cellular/Wi-Fi route selection, Windows firewall prompts, guest-network isolation, battery scheduling, reboot/startup behavior, installer execution, and device-specific codecs still require hardware checks. Emulator and loopback tests do not establish those results. Native originals remain retained when a codec is unavailable.
